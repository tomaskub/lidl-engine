# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` and `docs/adr/` at the root.

Before exploring an area, read `GLOSSARY.md` and relevant ADRs in `docs/adr/`. If they do not exist yet, proceed. `/domain-modeling` creates them when terms or decisions are resolved.

Use the glossary's terms in issues, proposals, and code. If a needed term is absent, check the project's language before adding it. Flag any conflict with an existing ADR explicitly.
